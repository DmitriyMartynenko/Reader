# Книги бібліотеки

Кожна книга — окрема тека `books/<id>/`. Збірка пакує її в один файл
`app/src/main/assets/books/<id>.book.json` і додає на полицю (`library.json`).
Застосунок нічого не знає про конкретні твори: усе, що він показує, береться з файлу книги.

## Що лежить у теці книги

| Файл | Що в ньому |
|---|---|
| `book.json` | Паспорт: назва, повна назва, автор, жанр, рік, колір обкладинки, підписи, **терміни** (як книга називає свої одиниці: «акт/сцена», для роману — «частина/розділ», і як називає репліки) |
| `build.json` | Як читати джерело: де починається текст, імена мовців оригіналу → id персонажів, імена в ремарках і ручні уточнення присутності |
| `source/original.txt` | Оригінал (для п'єс — у форматі Project Gutenberg) |
| `source/original.json`, `source/work/` | Розібраний оригінал і робочі аркуші для перекладу — створює `tools/parse.js` |
| `source/uk/<акт>-<сцена>.txt` | Переклад: `@place` — місце дії, `#<id>` — текст елемента з тим самим номером, що в оригіналі; `#<id> D` — це ремарка, `#<id> @МОВЕЦЬ` — інший мовець |
| `characters.json` | Профілі персонажів, їхні імена у відмінках (для підсвічування в тексті), події по актах |
| `pyramid.json` | Піраміда: ідея, акти, сцени, ключові моменти з прив'язкою до реплік |
| `perspectives.json` | Погляди персонажів: власна ідея, акти й сцени від першої особи, стани, події, смерть |
| `presence-facts.json` | Необов'язково: відомі факти «хто що чув» для перевірки |

## Як додати книгу

1. Створити `books/<id>/` з `book.json` і `build.json` (зразок — `books/othello/`), покласти оригінал у `source/original.txt`.
2. `node tools/parse.js <id>` — розібрати оригінал на сцени й пронумеровані елементи.
3. Перекласти `source/work/*.txt` у `source/uk/*.txt`.
4. Написати `characters.json`, `pyramid.json`, `perspectives.json`.
5. `node tools/build-book.js <id>` — зібрати файл книги; збірка зупиниться, якщо бракує перекладу, трапився невідомий мовець чи незрозуміла ремарка.
6. Перевірити: `node tools/check-pyramid.js <id>`, `check-perspectives.js <id>`, `check-presence.js <id>`, `check-names.js <id>`.
7. `gradlew testDebugUnitTest` — `BookContractTest` проганяє кожну книгу з полиці через ті самі вимоги пірамідальної структури.

Скрипт релізу сам перезбирає всі книги з `books/`.

## Путівник до твору, захищеного авторським правом

Якщо текст твору не можна включити (приклад — `books/la-confidential/`), книга стає **путівником**:
застосунок не містить жодного рядка оригіналу чи перекладу, лише піраміду, написану власними словами.

| Файл | Що в ньому |
|---|---|
| `build.json` | `{ "format": "guide" }` |
| `book.json` | як завжди, плюс `guide` (пояснення і підказка про власний примірник) і в `terms` — `actLabels`, `actShorts`, `actGenitiveLabels` («Пролог», «Частина I»…), `textTier` («Переказ»), `offstage` («немає поруч») |
| `source/guide/<частина>.txt` | розділи однієї частини: `== <kind> \| <назва> \| <скорочення> \| <чиїми очима або ->`, де kind — `prologue`, `chapter` чи `calendar`; далі `title:`, `place:`, `summary:`; `! ключовий момент` перед епізодом; `[id id …] епізод переказу` — у квадратних дужках ті, хто бере участь (з цього рахується присутність для поглядів персонажів) |
| `pyramid.json` | лише ідея й частини — розділи й моменти беруться з `source/guide` |
| `perspectives.json` | як у п'єси, але події, стани й смерть указують на епізод як `"<частина>.<розділ>#<n>"` (n-й епізод розділу); збірка перетворює це на номери, тож новий епізод нічого не зсуває |

Читач може додати **власний примірник** (FB2, FB2 у zip або EPUB): застосунок розбиває його за заголовками
(«Пролог», «Глава/Розділ/Chapter N», «Календар»; заголовки частин пропускаються), зіставляє з розділами путівника
за їхнім `kind` і зберігає лише в приватній пам'яті телефону. У репозиторій і в APK такі файли не потрапляють.
